# Phase 2 — Website Audit Report

**Scope:** `hno-alici-web` (branch `cms/phase2-4-audit-sanity`, baseline commit `cd5cb78`). Audited against the **local static build** (`npm run build` → `out/`, served via `npx serve out`), not the live production site, so results reflect the current source exactly. The live site's own HTML/assets were already captured separately in `DR_ALICI_WEBSITE_BACKUP\LIVE_SITE_SNAPSHOT` during Phase 1 if a production-vs-source diff is ever needed.
**Date run:** 2026-11-21.
**Scope seed:** `scripts/seo-report.mjs`'s hardcoded keyword/landing-page list was used to confirm which routes the business considers SEO-critical. That script itself is **not a crawler or checker** — it only prints keyword lists and a manual checklist — so it produced no findings of its own; all findings below come from direct tooling/code inspection.

**Tools used:** `linkinator` (broken links), `html-validate` (HTML conformance), `pa11y`/axe-core (WCAG AA accessibility), a custom Node+cheerio script (JSON-LD extraction/validation across all 62 built pages), and direct source reads for root-cause confirmation.

## Tooling results not requiring action

- **Broken links:** `linkinator --recurse` crawled 100 links from the local build — **0 broken**.
- **HTML validation:** `html-validate` reported 3,811 "errors," but the overwhelming majority are Next.js/React's own static-HTML serialization conventions (self-closing void elements like `<meta/>`, camelCase attributes like `hrefLang`/`fetchPriority`/`noModule`/`charSet`, React 19's `_R_`-prefixed hydration IDs, inline styles from `next/image` placeholders) — not actionable app bugs, and not something fixable without forking Next's own renderer. The genuinely actionable subset is extracted as findings G, H, I above and the `long-title` hit folded into finding F.
- **Dependency audit:** `npm audit` (run incidentally during `npm ci`) reports **18 vulnerabilities (8 moderate, 9 high, 1 critical)**. This is explicitly out of scope for this milestone's "Phase 4 CMS" work, but flagging now so it isn't lost — **carry into the next milestone's full Security Audit**, not fixed here.
- **Hreflang (general):** Aside from finding F, the two *correctly implemented* locale-exclusive pairs (`/de/tuerkischer-hno-arzt-wien` ↔ `/tr/turk-kbb-doktoru-wien` and `/de/kinder-hno-wien-1100` ↔ `/tr/cocuk-kbb-wien-1100`, from the canonical-page side) resolve as proper cross-slug alternates, not naive same-slug ones — this part works as intended.

## Explicitly needs human input, not fabricated

- Finding E (review ratings/testimonial authenticity) — cannot be verified or corrected by automated audit.
- Finding C (orphaned legal JSON deletion) — grep evidence of "unused" is not proof of safety for legal-document files; requires explicit human sign-off.
